# معماری Rust-first هستهٔ موسیقی Notli

## تصمیم اصلی

هستهٔ دامنه‌ای موسیقی Notli باید Rust باشد، نه یک هستهٔ Kotlin که صرفاً چند تابع Rust را صدا می‌زند. Rust مالک یگانهٔ تصمیم‌های پخش، وضعیت جاری، صف، ترتیب Shuffle، Repeat، انتخاب آهنگ، اعتبارسنجی فرمان‌ها، Snapshot و وضعیت دانلودهای موسیقی خواهد بود.

Android/Kotlin فقط لایهٔ اتصال به سیستم‌عامل است: اجرای خروجی صوت با Media3، دریافت callbackهای پلیر، دسترسی به MediaStore و مجوزها، اسکن فایل‌های محلی، انتقال HTTP و نوشتن فایل، Audio Focus، Foreground Service، MediaSession، اعلان‌ها و نمایش UI. این لایه نباید منطق صف یا تصمیم‌های اصلی پخش را دوباره پیاده‌سازی کند.

## محدودهٔ قابلیت‌ها

این بازطراحی فقط شامل موارد زیر است:
- پخش، توقف، مکث، ادامه، Seek و جابه‌جایی آهنگ
- صف پخش، Play Next، حذف/جابجایی آیتم، Shuffle و Repeat
- مدل آهنگ، شناسهٔ پایدار و منبع فایل/URI
- بازیابی Snapshot و حفظ سازگاری وضعیت پخش
- دریافت/دانلود مستقیم فایل موسیقی، وضعیت صف دانلود و پیشرفت
- هماهنگی رویدادها و فرمان‌ها بین Rust و آداپتر Android

قابلیت‌های نامرتبط NAVAQ مانند AVA، اجتماعی/اتاق، ساخت ملودی، پیشنهاد دوست، موسیقی DNA، کنترل خانه یا امکانات عمومی آن وارد Notli نمی‌شوند.

## ساختار پیاده‌سازی

پوشه native-core یک crate مستقل Rust است:
- model.rs: Track، TrackId، PlaybackState، PlayerCommand و قرارداد BackendAction/BackendEvent
- queue.rs: تنها مالک صف، cursor، Shuffle و اعتبارسنجی invariantها
- engine.rs: تنها مالک انتقال وضعیت و تصمیم‌های پخش؛ خروجی آن فرمان‌های قابل اجرای آداپتر و رویدادهای قابل انتشار است
- downloads.rs: وضعیت و اعتبارسنجی چرخهٔ عمر دانلودهای موسیقی؛ شبکه و فایل‌نویسی در Android انجام می‌شود
- lib.rs: سطح API عمومی crate

## قرارداد همگام‌سازی Android و Rust

جریان نهایی باید این باشد:

1. UI یا MediaSession یک فرمان موسیقی را به آداپتر Android می‌دهد.
2. آداپتر فرمان را به مدل نوع‌دار Rust تبدیل می‌کند و به هسته می‌فرستد.
3. Rust فرمان را اعتبارسنجی و اعمال می‌کند و CoreOutput شامل BackendActionها و PlayerEventها می‌دهد.
4. آداپتر فقط BackendActionها را با Media3 اجرا می‌کند.
5. callbackهای Media3 مثل Prepared، Position، Buffering، Ended و Failed به BackendEvent تبدیل و به Rust برگردانده می‌شوند.
6. Rust وضعیت نهایی و رویدادهای جدید را منتشر می‌کند؛ ViewModel/MediaSession/اعلان‌ها فقط مصرف‌کننده‌اند.

هر رویداد باید شناسهٔ Track فعلی را داشته باشد تا callback دیررس آهنگ قبلی نتواند وضعیت آهنگ جدید را خراب کند. Snapshotها باید نسخه‌دار و اتمیک باشند. خطای JNI یا Media3 باید به خطای نوع‌دار تبدیل شود و به Kotlin نشت نکند.

## وضعیت فعلی و محدودیت مهم

در این تغییر، crate اولیهٔ Rust برای مدل موسیقی، صف، ماشین وضعیت پخش، قرارداد Backend و مدیریت وضعیت دانلود ایجاد شده است. تست‌های واحد داخل crate نوشته شده‌اند، اما هنوز در CI اجرا نشده‌اند.

**اتصال JNI، ساخت کتابخانهٔ بومی برای ABIهای Android، اتصال واقعی ExoPlayer به BackendAction/BackendEvent و انتقال کامل مالکیت از PlaybackStateManager Kotlin هنوز انجام نشده است.** بنابراین در این مرحله نباید ادعا کرد موتور Rust جایگزین کامل مسیر Kotlin شده یا APK آمادهٔ انتشار است.

تا زمانی که پل و تست‌های رفت‌وبرگشت کامل نشده‌اند، مسیر قدیمی پخش حذف نمی‌شود. مهاجرت باید مرحله‌ای باشد و در هیچ لحظه‌ای دو صف یا دو منبع حقیقت فعال وجود نداشته باشد.

## اصول حفظ قابلیت‌های فعلی

- MusicRepository و Musikr فعلاً منبع دادهٔ کتابخانه و مدل‌های Android باقی می‌مانند؛ تبدیل به Track Rust فقط در مرز آداپتر انجام می‌شود.
- Media3 موتور خروجی صدا باقی می‌ماند؛ Rust تصمیم می‌گیرد چه چیزی و چه زمانی پخش شود.
- Room و PersistenceRepository تا زمان طراحی و تست نسخه‌بندی Snapshot حفظ می‌شوند.
- MediaSession، اعلان‌ها، ویجت‌ها، Audio Focus، اسکن کتابخانه و مجوزها از مسیر فعلی حفظ می‌شوند.
- هیچ قابلیت غیرموسیقایی از NAVAQ وارد پروژه نمی‌شود.
- تغییرات باید فقط روی شاخهٔ Noti انجام شوند؛ شاخه‌ها و پروژه‌های دیگر دست‌نخورده می‌مانند.

## اعتبارسنجی لازم پیش از ادغام

1. اجرای cargo test برای native-core.
2. اضافه‌کردن cross-compilation برای ABIهای مورد پشتیبانی Android و بارگذاری کتابخانهٔ JNI.
3. تست فرمان و رویداد رفت‌وبرگشتی با Media3، شامل خطا و callback دیررس.
4. تست صف، Shuffle/Repeat، Seek، بازیابی پس از بستن فرایند و دانلودهای pause/resume.
5. اجرای Android Build، Lint و تست دستگاه.
6. حذف منطق موازی Kotlin فقط پس از اثبات برابری رفتار و عبور تست‌ها.
